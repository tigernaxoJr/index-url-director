# 故事與分鏡指引

用於 `/video-story`（把使用者給的東西整理成完整故事）與 `/video-storyboard`（把故事切成 scene，寫旁白與對白）。角色長相與聲音在兩者之間的 `/video-design` 決定，見 [design-guide.md](design-guide.md)。

---

## 1. <a id="develop"></a>整理故事（`/video-story`）

### 先判斷手上有什麼

讀 `project.sources.story`（沒有時讀 `sources.description`），判斷是哪一種：

| 使用者給的 | 你要做的 |
|---|---|
| **完整故事**：有角色、有起因經過結果 | 不必提問。整理成 `brief/story.md`，只有在影片長度裝不下時提出刪減建議 |
| **大綱**：知道大致情節，缺細節 | 只問缺的部分（例如「小狐狸最後有沒有撈到月亮？」），一般 2–4 題 |
| **點子**：一句話或一個主題 | 依下面的順序一題一題補齊，一般 4–6 題 |

### 引導補完的提問順序

一次只問一題，每題給 2–3 個具體選項並標出你的建議，使用者也可以自己說。前面的回答會影響後面的選項。

1. **主角**：是誰、有什麼特點（「一隻很怕黑的小貓」）。
2. **主角想要什麼**：故事的動力（「想去屋頂看星星」）。
3. **阻礙**：為什麼做不到（「屋頂好黑，牠不敢上去」）。
4. **轉折**：誰或什麼讓情況改變（「螢火蟲來幫牠照路」）。
5. **結局**：怎麼結束，這是使用者的決定，**不要替他選**，只提供選項。
6. **想傳達的感覺**：溫馨、好笑、勇氣、感動…決定配樂與畫面的氣氛。

- 盡量用使用者的原句與命名；他說「小咪」就不要改成「小貓」。
- 使用者說「你決定就好」時，可以自己補，但寫完要在 checkpoint 講一次，讓他知道哪些是你補的。
- 角色控制在 1–4 個：每多一個角色，就多一套要畫的部件和一個聲音。

### 長度與段數

故事影片的節奏比產品影片慢，畫面要留時間給動作與表情。

| 目標長度 | scene 數 | 故事份量 |
|---|---|---|
| ≤ 45 秒 | 3–4 | 一個場景、一個轉折，例如寓言 |
| 46–90 秒 | 5–7 | 兩三個場景，有明確的起承轉合 |
| 91–180 秒 | 7–12 | 完整的短篇故事；角色 2–4 個 |
| > 180 秒 | 先建議拆成幾集 | 每集仍照上面的份量 |

旁白加對白的字數約為 **3.5 字／秒**（比產品影片慢，留給動作）。故事原文太長時，在 checkpoint 提出「保留哪些情節、哪些用旁白一句帶過」，等使用者選。

### 寫 `brief/story.md`

```markdown
# 小狐狸找月亮

一句話：一隻小狐狸以為月亮掉進池塘，想把它撈起來，最後明白月亮一直在天上陪著牠。

## 角色
- 小狐狸：橘色、大尾巴、好奇又急性子。主角。
- 貓頭鷹：老樹上的長輩，說話慢、很溫柔。

## 故事
### 開場
夜深了，森林裡很安靜……
### 鋪陳
…
### 衝突
…
### 高潮
…
### 結局
…

## 感覺與對象
溫馨、有一點好笑；給 4–7 歲的小朋友睡前看。
```

- 「故事」一節是完整的故事，不是大綱；之後的分鏡從這裡切。
- 有使用者的原文時，盡量沿用他的句子。

### <a id="confirm"></a>checkpoint：故事定稿

完成後用白話把故事從頭講一次（不要只給檔案），附上角色表，問：

1. 情節和結局對嗎？有沒有想改的地方？
2. 影片長度：依故事份量給 2–3 個選項並附理由，例如「60 秒（推薦：剛好講完三個場景）」「90 秒（可以多一段小狐狸試了好幾次的段落）」。

使用者確認後，以 `pnpm run state project --patch-file` 寫入 `project.targetAudience`、`project.style`（有調整時）、`project.format.targetDurationSec`，再 `pnpm run state project --status analyzed`。接著問他要不要開始設計角色。

## 2. <a id="storyboard"></a>分鏡、旁白與對白（`/video-storyboard`）

根據 `brief/story.md`、`brief/design.md` 與 `project.cast` 規劃 scene，產生每個 scene 的 `scene.json` 與 `script.md`。

### 切段

- **一個 scene 是一個畫面**：同一個地點、同一段連續的動作。換場景、時間跳躍、鏡頭大幅改變就換 scene。
- `purpose` 依起承轉合：`opening`（開場，建立地點與氣氛）→ `setup`（認識角色與他想要的）→ `conflict`（遇到阻礙）→ `climax`（最緊張或最關鍵的一刻）→ `resolution`（問題解決）→ `ending`（收尾的一句話或一個畫面）。段數多時同一種可以有好幾段；不必每種都有。
- 每段 5–15 秒。超過 15 秒的段落，畫面通常撐不住，拆成兩段。
- 第一段可以只有畫面和一句旁白；最後一段留 1–2 秒安靜的結尾畫面（`<!-- pause 1.5 -->` 放在最後）。

### <a id="dialogue"></a>寫旁白與對白（`script.md`）

```markdown
夜深了，森林裡的池塘亮亮的。
【小狐狸】哇！月亮掉進水裡了！
【小狐狸】我要把它撈起來！
<!-- pause 0.6 -->
小狐狸伸出爪子，水面一下子碎成好多片。
【貓頭鷹】孩子，抬頭看看。
```

- **以 `【角色名】` 開頭的行是那個角色說的**，用他在 `project.cast` 的聲音；名字要和 `cast[].name` 完全一樣（`pnpm run validate` 會檢查）。其他行是旁白，用 `project.tts` 的聲音。
- 【】要放在行首，一行只給一個角色；同一角色連續說好幾句，每行都要標。
- 對白不加引號，也不寫「小狐狸說：」，聲音本身就告訴觀眾是誰在說話。
- 寫給耳朵聽：短句（每句 ≤ 16 字），用小朋友聽得懂的詞（依對象調整）；狀聲詞（「噗通！」「咻——」）可以讓 TTS 念，效果不錯時就留著。
- 旁白負責「發生了什麼」，對白負責「角色的感覺」。同一件事不要旁白講完角色又講一次。
- `<!-- pause 秒數 -->` 留時間給動作與表情（例如角色愣住、回頭）；故事影片可以比產品影片多用，但每段不超過三個。
- 字幕會顯示說話內容（不含【角色名】）。

### 設計畫面（`scene.json` 的 `visual`）

故事的每一段都是 `motion-graphic`，由你寫的動畫模組畫出整個畫面。動畫模組怎麼寫見 [design-guide.md#animate](design-guide.md#animate)；分鏡時只要把畫面描述清楚，`assets/motion.js` 在 `/video-scene` 時才寫。

```json
{
  "$schema": "../../schemas/scene.schema.json",
  "id": "scene-003",
  "title": "池塘裡的月亮",
  "purpose": "conflict",
  "narration": { "scriptFile": "script.md" },
  "visual": {
    "type": "motion-graphic",
    "description": "夜晚池塘邊（近景）。小狐狸從左邊跑進來，趴在池邊看水裡的月亮，說話時尾巴搖；伸爪撈水，水波把月亮打散；貓頭鷹在右上的樹枝上眨眼說話。",
    "motion": { "file": "assets/motion.js", "uses": ["@/assets/cast/fox/", "@/assets/cast/owl/", "@/assets/sets/pond.svg"] },
    "transitionIn": "fade"
  },
  "durationSec": null,
  "status": "draft",
  "locked": false
}
```

- `visual.description` 寫清楚：**地點與鏡頭遠近、誰在畫面上、誰在什麼時候做什麼動作**。之後寫動畫、使用者在網頁上看，都靠這段描述。
- `motion.uses` 列出這段用到的角色資料夾（`@/assets/cast/<id>/`，結尾有 `/`）與場景、道具檔。列了，角色美術改了這段才會自動標示需要重做。`assets/motion.js` 在 `/video-scene` 才寫，分鏡時先寫好路徑即可（`pnpm run validate` 只檢查 `uses` 的檔案存在）。
- 片名、章節標題這類文字用 `elements` 的文字元素疊上去，不要畫在動畫裡。
- 轉場：同一個場景內的段落用 `fade` 或不用；換場景可以用 `wipe`。全片不超過兩種。

### 建立檔案

和產品影片相同（scene id、目錄命名、用 `pnpm run state project --patch-file` 寫入 `scenes`、驗證、設為 `script_generated`），見 [script-guide.md#files](https://aofa.tigernaxo.com/api/skills/product-video/script-guide.md#files)。目錄 slug 用簡短英文描述地點或事件，例如 `scenes/003-pond/`。

### <a id="review"></a>checkpoint：分鏡審閱

完成後**必須停下**。先給總覽表，再逐段列出完整的旁白與對白（不要用「…」省略）：

```text
目標 60 秒｜預估 58 秒｜6 段｜角色：小狐狸、貓頭鷹

| # | scene     | 段落 | 地點／畫面                     | 誰說話               | 秒數 |
|---|-----------|------|--------------------------------|----------------------|------|
| 1 | scene-001 | 開場 | 夜晚森林遠景，月亮升起         | 旁白                 | 7    |
| 2 | scene-002 | 鋪陳 | 小狐狸在草地上追螢火蟲         | 旁白、小狐狸         | 9    |
| 3 | scene-003 | 衝突 | 池塘邊，水中月亮被打散         | 旁白、小狐狸、貓頭鷹 | 12   |
| … |           |      |                                |                      |      |

【3 衝突｜約 12 秒｜池塘邊】
旁白：夜深了，森林裡的池塘亮亮的。
小狐狸：哇！月亮掉進水裡了！
…
畫面：小狐狸從左邊跑進來，趴在池邊…
```

- 秒數是估算，實際以產生語音後為準。
- 預估總長和目標長度相差超過 10% 時，先說明並問要刪減情節還是調整長度。
- 可以提醒使用者也能在網頁工作台直接改旁白和對白（記得保留行首的【角色名】）。
- 使用者提出修改時只改被點名的段落，改完再給一次更新後的表格。

使用者明確同意前，不執行 `tts` 或 `render:scene`。

## 3. <a id="revise"></a>重新規劃（已有 scene 時）

做法和產品影片相同，見 [script-guide.md#revise](https://aofa.tigernaxo.com/api/skills/product-video/script-guide.md#revise)：先提出逐段的保留／修改／新增／移除清單並等使用者確認，再寫入並執行 sync。故事影片另外注意：

- 改了 `brief/story.md` 的情節，先確認影響哪幾段，不要整部重寫。
- 新增角色要先回到 `/video-design` 畫好角色、定好聲音，再寫進分鏡。
- 只改某個角色的對白時，只有那幾段要重做語音與渲染。
